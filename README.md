# ЛР №2 — Каталог музичних альбомів (Dart)

**Предметна область:** варіант №8, каталог музичних альбомів.
**Тема:** об'єктно-орієнтована модель предметної області (Dart SDK 3.13+).

## Мета і функціональність

## Структура

- `bin/main.dart` — лише приклад використання бібліотеки, запуск і вивід.
- `lib/identifiable.dart` — контракт із незмінним ідентифікатором.
- `lib/album.dart` — незмінна сутність, первинний генеративний конструктор,
  `fromCsv`, кешувальний `unknown`, `==`, `hashCode`, гетери й валідація.
- `lib/album_extensions.dart` — розширення стандартного `String`.
- `lib/edition.dart` — `sealed`-ієрархія з 4 підтипами, поліморфний метод,
  `mixin on` для двох підтипів, вичерпний `switch` без `default`.
- `lib/genre.dart` — enhanced enum з полями, конструктором і гетером.
- `lib/repository.dart` — `Repository<T extends Identifiable>`.
- `lib/album_stats.dart` — агрегування з named record, розбір record
  та охоронюваний object pattern `when`.
- `test/` — тести сутності, ієрархії та сховища.
- `docs/experiments.md` — контрольовані експерименти `hashCode` та `switch`.

## Чому такі типи

- `String` — виконавець, назва, лейбл та ID: це текстові значення.
- `int` — рік випуску та кількість треків: цілі невід'ємні величини.
- `Duration` — тривалість, щоб не змішувати хвилини й секунди.
- `Album` — immutable value object: усі поля `final`, порівняння за значенням.
- `Map<String, T>` — пошук у репозиторії за ID без перегляду всього списку.
- `List<Album>` — впорядковане відображення; `Set<Album>` — експеримент
  зі знищенням дублікатів при узгоджених `==` та `hashCode`.
- `T extends Identifiable` — компілятор гарантує існування гетера `id`.
- `MusicGenre` enum — закритий набір підтримуваних жанрів без магічних рядків.
- `AlbumEdition` sealed — вичерпний switch під час додавання підтипів.
- named record — кілька статистичних результатів без зайвого класу DTO.

Первинний конструктор Dart 3.13 прибирає дублювання параметрів та
полів. Через перевірки в його тілі він не є `const`: для цієї моделі
важливіше відхиляти помилкові дані також у release-режимі, де `assert`
може не виконуватися.

Замість спадкування спільної поведінки від базового типу застосовано
`PlaylistBadge on AlbumEdition`: позначка потрібна лише Studio/Live,
але не Remastered/Compilation. Окрема ієрархія типів зберігає
спільний API опису релізів і дозволяє вибіркову поведінку.

## Залежності pub.dev та альтернативи

Виконання бібліотеки не використовує сторонніх залежностей.

- `lints` (`dev_dependency`) — офіційні рекомендовані правила для
  `dart analyze`. Альтернатива: вручну перераховувати правила або
  підключити сторонній набір `very_good_analysis`. Обрано офіційний
  мінімальний конфіг для навчального завдання.
- `test` (`dev_dependency`) — стандартний для екосистеми Dart пакет
  групування тестів і перевірок. Альтернатива: ручні `assert` або
  сторонні тестові фреймворки. Обрано `test`, оскільки він дає
  відтворюваний автоматизований результат.

`dart:core` та інші стандартні можливості Dart не потребують pub.dev.
Жодного використання `late`, `dynamic` чи оператора `!` в коді немає,
тому спеціального обґрунтування їх застосування не потрібно.
